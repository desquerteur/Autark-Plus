The Debian/Ubuntu lifecycle suite checks installation with checksum verification, active service, unprivileged service
user, listening web port, version, pairing output, data ownership/mode, repeated installation, update, restart,
uninstall with data retention, reinstall and purge. Containers created by these tests were removed after success;
the pre-existing `ubu2404` container was not modified. These are Incus systemd containers in WSL, not an actual
Proxmox host. The Debian 13 configuration records a non-privileged UID mapping.

The fetched public-main installer and the release-worktree installer were byte-identical (SHA-256
`6af08a3bd870c19cce9fd22e9ed04c4e65eeda257a3d206e1b8b72a18ea25e55`).

## Limits and security scope

- macOS arm64/x64 zips are ad-hoc signed and structurally checked, but have not been launched on real Macs.
- The Android screenshot also shows an emulator **System UI** non-response dialog. The Autark connection screen
  rendered behind it and its process remained alive. This proves installation/start, not responsive end-to-end pairing.
- The x64 Linux lifecycle tests do not establish native ARM64 hardware compatibility.
- Windows is not publisher-code-signed; macOS is not notarized. Checksums prove file integrity, not publisher identity.
- No application code, backend authorization rules or dependencies were changed by this verification. This is not a
  new comprehensive security audit. The documentation now explicitly warns that the server installer runs as root.
